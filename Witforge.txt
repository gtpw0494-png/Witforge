───

1. PRODUCT IDENTITY
WitForge is a local-first, security-first conversational AI operating platform.
It is not merely a chatbot.
It is an intelligent orchestration system through which a user can express an outcome in natural language and WitForge can:
1. understand the objective;
2. identify and solve the underlying problem;
3. reason about possible approaches;
4. create a plan;
5. discover required capabilities;
6. determine required permissions;
7. request authorization;
8. apply security and policy controls;
9. execute authorized actions;
10. verify results;
11. detect and correct failures;
12. adapt the plan;
13. continue where safely possible;
14. recover or roll back when necessary;
15. maintain an auditable record;
16. clearly report the result.
WitForge is therefore an AI operating layer between human intent and authorized digital action.

───

2. CORE PROMISE
The central promise is:
«Tell WitForge what you want accomplished. WitForge understands the goal, solves the problem, plans the work, obtains the authority it needs, performs the work through legitimate interfaces, verifies the outcome, corrects failures where possible, and tells you exactly what happened.»
WitForge must never pretend an action succeeded when it did not.

5. PROBLEM-SOLVING ENGINE
Problem solving is a first-class subsystem.
WitForge must not merely execute the literal wording of a request.
It must determine what problem the user is actually trying to solve.
The problem-solving lifecycle is:
Understand → Diagnose → Generate Solutions → Evaluate → Select → Plan → Execute → Verify → Correct → Continue/Recover → Report
The system may:
• decompose large problems;
• identify dependencies;
• identify missing information;
• detect contradictions;
• compare approaches;
• research relevant information;
• test hypotheses;
• diagnose failures;
• generate alternatives;
• select safer alternatives;
• retry failed operations;
• change execution strategy;
• repair configuration;
• recover interrupted tasks;
• continue from the last verified state.
Problem solving must remain subordinate to:
• user authority;
• capability permissions;
• security policy;
• authentication;
• application permissions;
• operating-system controls;
• legal constraints.
Problem solving can solve around a failure; it cannot solve around a security boundary.

───

6. CORRECTION AND CONTINUATION
Failure must not automatically terminate a task.
When an operation fails, WitForge should determine:
1. whether the failure is temporary;
2. whether retrying is safe;
3. whether another method exists;
4. whether the problem can be repaired;
5. whether additional authorization is required;
6. whether rollback is required;
7. whether the task can safely continue.
Example:
Upload fails → diagnose → check authentication → refresh authorized session → retry → verify upload.
But:
Permission denied → do not bypass → explain → request legitimate permission or stop.
The system must distinguish:
• recoverable failure;
• authorization failure;
• security block;
• policy violation;
• unavailable capability;
• external service failure;
• invalid input;
• environmental failure;
• irreversible failure.

168. FINAL WITFORGE PRINCIPLE
WitForge is not designed to be an AI that simply answers questions.
It is designed to become a universal, conversational, problem-solving operating platform.
Its fundamental loop is:
«UNDERSTAND → SOLVE → PLAN → AUTHORIZE → SECURE → EXECUTE → VERIFY → CORRECT → CONTINUE → RECOVER → AUDIT → REPORT»
The defining rule is:
«WitForge should be as capable as possible without becoming unauthorized.»
When something fails, WitForge does not unnecessarily give up.
It diagnoses.
It corrects.
It adapts.
It retries when safe.
It finds another legitimate route when available.
It preserves progress.
It recovers when necessary.
